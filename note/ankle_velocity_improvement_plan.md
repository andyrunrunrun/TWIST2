# 踝关节速度处理改进计划

> **问题**: 部署时踝关节速度置零导致locomotion性能下降  
> **根因**: 训练时使用完整速度，部署时因VR噪声被迫置零，形成Sim-to-Real Gap  
> **目标**: 在抑制噪声的同时保留有用信号

---

## 📊 问题概述

### 当前状态
| 阶段 | 踝关节速度 | 代码位置 |
|------|-----------|---------|
| 训练 | ✅ 完整使用 | `humanoid_mimic.py:645` |
| 部署 | ❌ 强制置零 | `server_low_level_g1_real.py:203` |

### 受影响的关节
- `left_ankle_pitch_joint` (索引4)
- `left_ankle_roll_joint` (索引5)  
- `right_ankle_pitch_joint` (索引10)
- `right_ankle_roll_joint` (索引11)

## 🎯 改进方案优先级

### Phase 1: 信号滤波（推荐首先尝试）

**目标**: 保留低频信号，去除高频噪声

**方案1.1: 低通滤波器**
```
文件: deploy_real/server_low_level_g1_real.py
修改: 在 __init__ 中添加滤波器，在观测构建时使用
参数: cutoff_freq = 5-10 Hz
```

**方案1.2: 移动平均滤波**
```
窗口大小: 3-5帧
优点: 实现简单
缺点: 引入延迟
```

**方案1.3: 卡尔曼滤波**
```
process_noise: 0.01
measurement_noise: 0.1-0.5
优点: 自适应，延迟小
缺点: 需要调参
```

**验证方法**: 
1. 在 sim2sim 测试滤波效果
2. 记录滤波前后的信号对比
3. 真机测试locomotion稳定性

---

### Phase 2: 训练时Domain Randomization

**目标**: 让策略从训练阶段就适应噪声/置零

**方案2.1: 踝关节速度噪声注入**
```
文件: legged_gym/envs/base/humanoid_mimic.py
位置: compute_observations()
参数: ankle_noise_std = 1.0-2.0 rad/s
```

**方案2.2: 随机置零**
```
概率: 20-50%
作用: 让策略学会不依赖踝关节速度
```

**方案2.3: 信号裁剪**
```
范围: [-1.0, 1.0] rad/s
作用: 限制异常值影响
```

**验证方法**:
1. 对比有无DR的策略性能
2. 在sim2sim中测试鲁棒性
3. 真机locomotion对比测试

---

### Phase 3: 信号可信度评估

**目标**: 动态判断信号质量，智能决策

**方案3.1: 变化率阈值**
```
if |current_vel - last_vel| > threshold:
    use_filtered_or_zero()
else:
    use_raw_value()
```

**方案3.2: 方差监控**
```
计算滑动窗口内的方差
方差过大 → 降低信号权重
```

**方案3.3: 物理约束检查**
```
if |ankle_vel| > physical_limit:  # 如 10 rad/s
    信号不可信
```

## ⚠️ 风险与注意事项

1. **滤波延迟**: 过度滤波会引入延迟，影响响应速度
2. **过拟合DR**: 噪声参数需要匹配真实分布
3. **性能回归**: 每次修改都需要完整测试
4. **硬件差异**: 不同VR设备噪声特性不同
